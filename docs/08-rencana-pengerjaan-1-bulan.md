# Rencana Pengerjaan MVP PERINTIS — 1 Bulan

## Prinsip perencanaan

Targetnya adalah MVP yang dapat digunakan dan didemokan dalam satu bulan. Rencana ini bukan jadwal final per tanggal karena tanggal mulai dan ketersediaan waktu harian belum ditetapkan.

## Minggu 1 — Finalisasi desain dan fondasi proyek

- [ ] Audit dan setujui desain desktop Google Stitch.
- [ ] Pastikan 19 item fitur MVP tercakup.
- [ ] Finalisasi design tokens dan komponen global.
- [ ] Adaptasi awal struktur desain untuk mobile bila desktop sudah disetujui.
- [ ] Tetapkan stack dan provider autentikasi.
- [ ] Setup Next.js, TypeScript, Tailwind, komponen UI.
- [ ] Setup database dan environment.
- [ ] Buat struktur folder dan layout aplikasi.
- [ ] Implementasikan authentication dasar.

**Output:** proyek berjalan, fondasi UI, navigasi global, dan autentikasi dasar.

## Minggu 2 — Personal Growth

- [ ] Onboarding & Personal Assessment.
- [ ] Dashboard Overview.
- [ ] My Direction / Goal Management.
- [ ] Remember Your Why.
- [ ] My Roadmap.
- [ ] Know Your Next Step.
- [ ] Integrasi data antarfitur.

**Output:** pengguna dapat membuat tujuan, menyimpan alasan, menyusun roadmap, dan menentukan langkah berikutnya.

## Minggu 3 — Daily Execution dan Coach

- [ ] Daily Guidance.
- [ ] Task Reschedule / Skip.
- [ ] My Habits.
- [ ] Reminder & Notification versi realistis untuk MVP.
- [ ] Personal Coach.
- [ ] My Commitment dengan aturan keselamatan.
- [ ] Calendar View.
- [ ] Profile & Settings dan Theme Customization.

**Output:** pengguna dapat menjalankan rencana harian dan mengelola aktivitas/kebiasaan.

## Minggu 4 — Evaluation, pengujian, dan demo

- [ ] Daily Reflection.
- [ ] Weekly Growth Review.
- [ ] Progress Analytics berdasarkan data nyata.
- [ ] Pengujian alur utama dari register sampai refleksi.
- [ ] Pengujian validasi form dan hak akses data.
- [ ] Perbaikan bug prioritas tinggi.
- [ ] Pengujian responsive desktop/mobile.
- [ ] Deployment.
- [ ] Siapkan data demo dan skenario presentasi.

**Output:** MVP terdeploy dan dapat didemokan.

## Prioritas ketika waktu mulai terbatas

1. Jangan korbankan keamanan dasar dan pemisahan data antaruser.
2. Pastikan alur utama end-to-end berjalan.
3. Sederhanakan fitur pendukung, bukan menambah scope.
4. Gunakan komponen bersama untuk menghemat waktu.
5. Tunda animasi/dekorasi yang tidak mendukung alur.
6. Jangan membuat statistik palsu untuk mengisi dashboard.

## Definisi selesai (Definition of Done) MVP

- Aplikasi dapat dijalankan dan diakses melalui deployment.
- Pengguna dapat register/login/logout.
- Data pengguna tersimpan dan tidak bercampur dengan pengguna lain.
- Pengguna dapat menyelesaikan alur tujuan → roadmap → aktivitas → refleksi.
- Pengguna dapat mengubah, menjadwalkan ulang, atau melewati aktivitas.
- Halaman utama dapat digunakan di desktop dan mobile.
- Tidak ada fitur mockup yang diklaim berfungsi jika belum diimplementasikan.
- Bug kritis pada alur utama sudah ditangani.
